1. Система контролю версій Git

VCS Engine

Архітектура та 4 стани файлів у Git

На відміну від застарілих централізованих систем (SVN, CVS), Git зберігає дані як набір знімків стану (snapshots) міні-файлової системи та працює через 4 ключові робочі області:

Зона 1
Working Directory
Ваші реальні файли на диску, де ви пишете код або змінюєте контент.
git add . ➔
Зона 2
Staging Area (Index)
Проміжний буфер підготовлених файлів, які увійдуть до наступного коміту.
git commit ➔
Зона 3
Local Repository
Локальна база об'єктів (.git), де зберігається повна історія комітів та гілок.
git push ➔
Зона 4
Remote Repository
Хмарний або віддалений сервер (GitHub, GitLab, Bitbucket) для командної співпраці.
git fetch / pull
  • Децентралізація Кожен клон репозиторію є повноцінним резервним сервером.
  • Контрольна сума SHA-1/256 Неможливо змінити байт у файлі без зміни хешу всього коміту.
  • Дешеві гілки (Branches) Гілка в Git — це всього лише 41-байтний вказівник на конкретний коміт.

Корисні команди: конфігурація та щоденний цикл

git config --global user.name "..."

Встановлення глобального імені автора для всіх комітів.

git init

Створення нового репозиторію та ініціалізація каталогу .git.

git status -s

Короткий та інформативний статус файлів (?? новий, M змінений, A доданий).

git log --oneline --graph --all

Візуалізація дерева всіх гілок та комітів у вигляді графа в один рядок.

git diff --staged

Перегляд різниці (diff) між підготовленими файлами в Staging та останнім комітом.

Скасування змін, Rebase та тимчасове збереження (Stash)

Одна з найсильніших переваг Git — можливість безпечно виправляти помилки на будь-якому етапі розробки:

Команда Дія Рівень безпеки
git restore <file> Скидає незакомічені зміни у робочій директорії до стану HEAD. ⚠️ Втрата незбереженого коду
git restore --staged <file> Видаляє файл зі Staging Area, повертаючи його у стан "змінений". ✅ Абсолютно безпечно
git reset --soft HEAD~1 Скасовує останній коміт, але залишає всі написані зміни у Staging. ✅ Безпечно (код на місці)
git reset --hard HEAD~1 Повністю знищує останній коміт та всі пов'язані файли з диска! 🛑 Небезпечно! Непоправне видалення
git revert <hash> Створює новий коміт, який дзеркально нейтралізує зміни старого коміту. ✅ Безпечно для публічних гілок
git stash push -m "msg" Ховає незавершені зміни у кишеню (стек) для швидкого перемикання гілок. ✅ Безпечно (потім: git stash pop)

Merge проти Rebase: У чому різниця?

git merge: Зберігає всю хронологічну правду з історією переплетень гілок та створює спеціальний "Merge commit". Ідеально для вливання готових гілок у головну гілку main.

git rebase: Переносить основу вашої гілки на верхівку цільової, переписуючи хеші комітів. Створює ідеально пряму лінійну історію без зайвих мердж-комітів. Золоте правило: ніколи не робіть rebase у спільних публічних гілках!

2. Операційна система GNU/Linux

UNIX System

Файлова ієрархія Linux (FHS)

У Linux діє фундаментальний принцип UNIX: «Все є файлом» (навіть жорсткі диски, мережеві сокети та процеси). Всі шляхи беруть початок від єдиного кореня / (Root):

/bin та /usr/bin
Основні бінарні виконувані файли та команди для користувачів (bash, ls, grep).
/etc
Конфігураційні файли всієї системи (налаштування мережі, демонів, Nginx).
/home/<user>
Особисті каталоги користувачів системи з їхніми документами та конфігами.
/var/log
Змінні дані, черги завдань та системні журнали (лог-файли) служб.

Права доступу до файлів (chmod & chown)

Кожен файл і папка в Linux мають права для трьох категорій: U (Власник), G (Група) та O (Всі інші). Кожна дія має свою числову вагу:

Символ Дія Числова вага Приклад розрахунку для файлу
r (Read) Читання вмісту файлу / перегляд папки 4 chmod 755 script.sh
Власник (7 = 4+2+1): Читання, Запис, Запуск.
Група (5 = 4+1): Читання, Запуск.
Інші (5 = 4+1): Читання, Запуск.
w (Write) Запис, редагування або видалення 2
x (Execute) Виконання програми або вхід у теку 1

3. BASH Scripting & Потоки даних

Automation

Стандартні потоки введення/виведення та конвеєри (Pipes)

Кожен процес, який запускається у терміналі, автоматично отримує три файлові дескриптори:

  • 0: STDIN (Standard Input) Потік введення (за замовчуванням клавіатура).
  • 1: STDOUT (Standard Output) Потік нормального виводу успішних результатів.
  • 2: STDERR (Standard Error) Потік для повідомлень про помилки та діагностики.

Оператори перенаправлення:

command > file.txt

Перенаправлення STDOUT у файл із повним перезаписом вмісту.

command >> file.txt

Перенаправлення STDOUT у файл із дописуванням у кінець (Append).

cmd1 | cmd2

Конвеєр (Pipe): вивід STDOUT першої команди стає STDIN для другої команди.

command > output.log 2>&1

Об'єднання потоків: спрямовує і помилки (2), і нормальний вивід (1) в один файл.

Практичні скрипти автоматизації

Оберіть скрипт для перегляду вихідного коду:

#!/bin/bash
# Симуляція безпечного входу в систему Linux

CORRECT_USER="admin"
CORRECT_PASS="secret123"

echo "=== СИСТЕМА АВТОРИЗАЦІЇ LINUX ==="
read -p "Введіть логін: " username

# Прапорець -s приховує введення символів пароля
read -s -p "Введіть пароль: " password
echo ""

if [[ "$username" == "$CORRECT_USER" && "$password" == "$CORRECT_PASS" ]]; then
    echo "✅ Авторизація успішна! Ласкаво просимо, $username."
    echo "Час сесії: $(date)"
    exit 0
else
    echo "❌ Помилка: Невірні облікові дані!" >&2
    exit 1
fi
#!/bin/bash
# Моніторинг системних ресурсів: ОЗП, Диск, Навантаження

echo "=== ЗВІТ ПРО СТАН СЕРВЕРА [$(hostname)] ==="
echo "Дата: $(date)"

echo -e "\n1. Використання оперативної пам'яті (RAM):"
free -h | awk 'NR==1 || NR==2'

echo -e "\n2. Вільне місце на дисках:"
df -h --output=source,size,used,avail,pcent,target -x tmpfs -x devtmpfs

echo -e "\n3. Середнє навантаження системи (Load Average):"
uptime | awk -F'load average:' '{ print $2 }'
#!/bin/bash
# Скрипт автоматичного комміту та синхронізації з Git

COMMIT_MSG="${1:-Автоматичне оновлення $(date +'%Y-%m-%d %H:%M')}"

echo "🔍 Перевірка статусу сховища..."
git status -s

echo "📦 Додавання файлів до Staging Area..."
git add .

echo "💾 Фіксація коміту: '$COMMIT_MSG'"
git commit -m "$COMMIT_MSG"

if [ $? -eq 0 ]; then
    echo "🚀 Відправка до віддаленого репозиторію..."
    git push origin HEAD
    echo "✅ Синхронізацію успішно завершено!"
else
    echo "ℹ️ Немає нових змін для відправки."
fi

Швейцарський ніж Linux-інженера

grep -rn "pattern" .

Рекурсивний пошук тексту у всіх файлах з номерами рядків.

find . -name "*.log" -size +10M

Пошук файлів за розширенням, які займають більше 10 Мегабайт.

awk '{print $1, $4}' file.txt

Потужна потокова обробка колонок та генерування звітів із логів.

sed -i 's/old/new/g' file.txt

Миттєвий пошук та заміна тексту безпосередньо у файлі без відкриття редактора.
